# SCP-Fast 1.1.1

在 VS Code 的 Remote-SSH 默认资源管理器中，使用 **Windows 本机 OpenSSH scp** 上传、下载文件。大文件内容由 scp 直接传输，扩展只处理队列、认证、进度和文件提交。

## 安装

1. 在 Windows 本机 VS Code 中执行 **Extensions: Install from VSIX…（扩展：从 VSIX 安装）**，选择 `scp-fast-1.1.1-win32-x64.vsix`。
2. 使用 Remote-SSH 打开 Linux 服务器上的目录。扩展运行在本机，服务器不需要安装 SCP-Fast。
3. 在服务器文件或文件夹上右键，即可看到下列菜单。可通过 **Developer: Show Running Extensions** 检查扩展的运行位置。

要求：Windows 10/11 x64、VS Code 1.100+、本机 OpenSSH 9.0+；Linux SSH 服务器提供 SFTP 子系统。Windows 本机已提供 .NET Framework 4.x；VSIX 内含认证辅助程序，无需安装 Node.js、Go 或编译器。

从旧版升级后，执行 **Developer: Reload Window（开发人员：重新加载窗口）**。扩展安装在本机，连接的服务器沿用现有 SSH 服务。

## 操作

| 右键位置 | 菜单 | 操作 |
| --- | --- | --- |
| 单个服务器文件 | 快速下载到本机 | 选择本机保存目录 |
| 单个服务器文件夹 | 快速下载到本机 | 保留文件夹名称、内部层级和空文件夹 |
| 多个服务器文件／文件夹 | 批量下载到本机 | 选择一次保存目录，逐个下载 |
| 单个服务器文件夹 | 上传本机文件到此处 | 选择一个或多个本机文件 |

资源管理器下方的 **SCP-Fast 传输** 视图显示上传、下载任务。文件名旁边显示方向、进度、已传大小、速度和粗略剩余时间；悬停可看完整中文路径及错误。界面不显示具体秒数，点击任务可在日志中查看耗时。

- 上传与下载共用 FIFO 队列，同一窗口同时传一个文件。不同窗口队列独立。
- 活跃任务旁的停止按钮取消该任务；等待中的任务也可以取消。正式文件提交阶段不可取消。
- 失败、取消或中断的任务可以从头重试。重试会再次检查重名和源文件。
- 成功下载后可以打开 Windows 本机所在文件夹；上传后刷新远端资源管理器。
- 按服务器分别记住最近下载目录和上传文件选择位置。
- 完成提示不会阻塞下一项传输。

## 文件夹下载

右键服务器文件夹，选择 **快速下载到本机**，再选择本机保存目录。例如下载服务器的 `模型` 文件夹到 `D:\下载`，结果为 `D:\下载\模型\...`。

扩展先读取目录结构，再通过本机 scp 逐个传输文件；不压缩、不在服务器创建打包文件。保留空目录和目录层级，跳过符号链接及特殊文件，扫描过程可以取消。

每次选择的顶层文件夹在队列及历史记录中只占一条，不展开子文件或子目录。显示已处理文件数、累计已传大小、当前速度和整体结果；百分比按已处理文件数及当前文件进度估算，不表示整个目录的字节比例。内部文件明细合并到文件夹日志中，旧版记录也按文件夹合并。单独选择的文件仍各自显示。

本机已有同名目录时合并内容，额外文件保留；已有同名文件继续使用覆盖确认。每个文件分别用临时文件提交，整个文件夹不是一次原子替换。取消文件夹会停止当前文件和剩余排队任务，已成功下载的文件及已创建目录保留。目录创建失败会取消其下尚未开始的任务；在文件夹记录上重试，会把失败、取消或中断的内容重新排队，每个未成功文件从头传输。成功后“打开本机文件夹”打开下载的根文件夹。

目录扫描得到的是开始下载时的清单，扫描后新增的文件需要再次下载。每个文件传输时仍会检查源文件是否发生变化。大量小文件需要多次 SSH 连接，可能比一次打包传输更慢；当前版本未提供打包模式。

## SSH 与认证

优先使用 SCP-Fast 的本机设置，再沿用 Remote-SSH 的 `remote.SSH.path` 与 `remote.SSH.configFile`，最后使用 Windows OpenSSH 默认程序和 `~/.ssh/config`。

扩展直接传入 SSH 主机别名与原配置文件，因此端口、用户、密钥、ProxyJump、ProxyCommand、Include 和 Match 仍由 OpenSSH 解析。无法自动匹配时，首次选择已有的具体 `Host` 条目；命令 **SCP-Fast: 重新选择当前服务器 SSH 条目** 可更换映射。

支持 SSH 密钥、ssh-agent、密码、带口令密钥和交互认证。认证输入出现在 VS Code 遮蔽输入框中；首次主机信任请求会单独确认。密码和验证码不落盘，不进入任务日志。

每个 scp 任务建立自己的 SSH 连接，因此密码方式可能逐个询问。需要减少询问时，可使用已加载到 ssh-agent 的密钥。

| 本机设置 | 作用 |
| --- | --- |
| `scpFast.scpPath` | 指定本机 scp.exe |
| `scpFast.sshPath` | 指定本机 ssh.exe |
| `scpFast.sshConfigPath` | 指定本机 SSH 配置文件 |
| `scpFast.diagnosticLogging` | 对后续任务启用 scp -v 详细日志 |

建议 ssh.exe 和 scp.exe 来自同一套 Windows OpenSSH。扩展不修改 SSH 配置，不关闭主机指纹校验。

## 重名与临时文件

目标存在时，选择覆盖、跳过或取消本批次；覆盖确认只针对这个文件。每项任务先传入目标目录内的 `.<原文件名>.scp-fast-<时间戳与序号>.part` 文件。scp 成功退出、源文件未变化且大小一致后，才重命名为正式文件。临时命名不使用文件哈希，界面与日志仅展示原文件名。

原正式文件在传输过程中保留。目标在传输期间变化时会再次询问。目录、符号链接和特殊文件不会被覆盖。仅传普通文件，不跟随符号链接。

失败或取消时清理本任务的临时文件。若完整文件已经传完，但最终校验、确认或重命名失败，则保留完整临时文件供手动取回。带临时文件的记录不会被“清除已结束任务”移除。

窗口关闭或扩展重载后，未完成任务标为中断，需要手动重试。日志以原文件名标识临时位置；实际目录内可按原文件名前缀找到遗留临时文件。

## 进度、速度与日志

扩展直接启动本机 scp，不经过伪终端。每秒读取目标临时文件大小，计算已传大小、百分比、速度和预计剩余时间，界面标识为“估算”。无论显示多少，必须等到 scp 退出、校验并提交成功才算完成。

界面显示平均传输速度；具体传输耗时、含准备和认证等待的总耗时，以及准备、认证等待、scp、校验和提交的分段耗时保留在日志中。日志路径显示中文字符，标签使用原文件名；内部任务标识不展示。日志保存在扩展的本机存储中，每项原始输出最多 2 MB，保留最近 100 份；输出面板名为 **SCP-Fast**。日志可能包含主机、用户名和文件路径，分享前请检查。

速度目标：相近网络条件下，同一文件的插件端到端耗时（扣除人工输入等待）不超过同配置命令行 scp 的 115%。已归档的约 400 MB 文件测试中，传输核心总耗时比同轮原生 scp 多约 1.8%；实际窗口表现取决于当前网络和远端连接，测试范围见源码中的 `docs/VALIDATION.md`。

## 支持范围

支持单文件及多文件排队上传、下载，以及服务器文件夹的递归下载。上传仍选择本机文件，服务器文件夹作为上传目标。不包含本机文件夹上传、压缩传输、暂停、断点续传、自动同步或独立 SFTP 文件浏览器。

远端文件名必须可保存到 Windows；非法字符、保留名称和结尾空格／点需要先在服务器上重命名。Windows OpenSSH 会改写反斜杠，远端路径中含反斜杠的目录也需先重命名。本机大小写不敏感；同一下载清单里名字仅大小写不同的路径会在开始前报错，需分开下载或先重命名。
